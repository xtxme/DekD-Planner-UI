# README Evaluator Guide Design

## Goal

ปรับ `README.md` ให้เป็นเอกสารหลักสำหรับผู้ประเมิน Android APK โดยอ่านแล้วเข้าใจภาพรวมของแอป, วิธีติดตั้ง, วิธีทดสอบ, ข้อกำหนดของ backend, และข้อจำกัดที่ควรรู้โดยไม่ต้องไล่อ่านหลายไฟล์

## Audience

- อาจารย์หรือผู้ประเมินที่ต้องการติดตั้งและลองใช้งานแอปบน Android
- ผู้ช่วยสอนหรือเพื่อนร่วมทีมที่ต้องการรู้ว่าต้องส่งอะไรพร้อม APK

## Recommended Approach

ใช้โครงแบบ evaluator-first ใน `README.md` แล้วเก็บข้อมูลสำหรับนักพัฒนาไว้เป็นส่วนสั้นท้ายไฟล์เท่านั้น เพื่อให้ผู้อ่านหลักเห็นข้อมูลที่จำเป็นต่อการประเมินทันที

## Content Structure

1. ชื่อโปรเจกต์และสถานะว่า README ฉบับนี้ใช้สำหรับ Android APK submission
2. สรุปว่าแอปทำอะไรได้บ้างในระดับผู้ใช้
3. ข้อมูล repository และตำแหน่งไฟล์ APK
4. ขั้นตอนติดตั้งและเปิดใช้งานบน Android
5. ข้อมูล evaluator account และข้อมูลที่ต้องกรอกก่อนส่ง
6. ลำดับการทดสอบที่แนะนำ
7. หมายเหตุเรื่อง backend และ environment
8. ข้อจำกัดที่ผู้ประเมินควรรู้
9. หมายเหตุสำหรับผู้พัฒนาแบบสั้น

## Constraints

- ห้ามใส่ credential จริงใน repository
- ต้องชี้ให้ชัดว่าผู้ส่งต้องกรอก backend และบัญชีทดสอบก่อนส่งจริง
- ต้องระบุความเสี่ยงสำคัญ เช่น backend ที่เข้าถึงได้เฉพาะ localhost และข้อจำกัด `--no-tree-shake-icons`

## Success Criteria

- อาจารย์อ่าน `README.md` แล้วรู้ว่าต้องใช้ไฟล์ไหน, ติดตั้งอย่างไร, login ด้วยอะไร, และควรตรวจฟีเจอร์ไหน
- README ไม่ปนรายละเอียดเชิงพัฒนามากจนรบกวนการประเมิน
- ข้อมูลสำคัญสอดคล้องกับ `docs/submission/android-apk-submission.md`, `.env.example`, และ Android config ปัจจุบัน
